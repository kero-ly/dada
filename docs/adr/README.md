# 架构决策记录（ADR）

本目录记录**已经做过的、会影响后续所有代码的技术决策**。一页一个决策，写完不轻易改；
需要推翻时新写一份并把旧的状态改成「已取代」。

## 为什么要 ADR

初期的架构讨论放在 `docs/architecture/platform-4plus1.html`（一份 68KB 的 HTML），
问题是：它不会随实现更新，半年后没人知道哪条还作数。ADR 的规则是
**一条决策一个文件、带日期和状态、只有「提议 / 已接受 / 已取代 / 已废弃」四种状态**，
维护成本接近零，但能回答「当初为什么这么定」。

## 写作约定

- 文件名 `NNNN-slug.md`，编号递增不复用。
- 必填小节：**状态 / 背景 / 决策 / 后果 / 备选方案 / 未决问题**。
- **正文用中文，开头给一段英文摘要**，让非中文贡献者能判断这份文档是否与自己相关。
- 决策一旦落地，就把「状态」改成「已接受」，并在这里的索引同步。
