已购买金逸晨 ESP32-C3 2.4 寸触摸开发板，当前从 C3 串口启动、屏幕与触摸验证开始，再做离线番茄钟。下方 S3 双板采购与排期属于此前方案，暂不执行；长期平台边界仍保留。工程现状见仓库 README.md 与 docs/architecture/c3-bootstrap.md。

首轮目标：同一 S3 系列 × 两套硬件组合 × 两个应用

建议按 15–20 个有效工作日安排，前提是一名能处理 ESP-IDF 与 C/C++ 的开发者持续投入、硬件到货且参考驱动可用。这是排期假设，不是交付承诺；遇到驱动问题优先缩小外设范围。

通过标准：两个离线应用都能在 A、B 两套硬件运行；换板只改硬件包与配置，不修改业务源码；更换应用不复制驱动。首期源码级复用，每台设备一次运行一个应用固件。

00 · 适配路线：固定 S3，先把板子与组件组合做通

首期只做 ESP32-S3＋PSRAM：先改变屏幕、输入和板级接线，检验应用是否可迁移。C3、C6 属于后续芯片扩展，首批不采购、不并行适配。当前通过两套 S3 硬件，只能证明已测试组合兼容，不能宣称支持全部 S3 板子。

层次首期职责复用边界
芯片 / SDK 适配锁定 ESP-IDF 的 S3 目标及工具链；统一系统、网络、总线等必要接口。尽量复用 ESP-IDF，不为每块 S3 板重写芯片底层。
组件驱动与参数显示驱动、触摸驱动、GPIO 按键分别组织；屏幕尺寸、方向、色序和偏移独立配置。同一控制器的兼容模块共用驱动；具体初始化差异允许参数或专用实现。
基础板支持包记录主控、Flash / PSRAM、硬件修订、可用引脚与电源限制。固定产品板描述板载外设；通用 DevKit 留出外接组件配置。
硬件组合配置引用基础板和组件版本，明确 GPIO、总线、供电、输入映射及能力声明。用户选择的是完整硬件配置；缺失或冲突时给出诊断，不仅选择“ESP32-S3”。
应用包专注时钟与互动角色依赖标准显示、输入、时间和存储能力。业务中不写板型分支；布局允许依据尺寸调整，触摸与按钮映射为约定动作。

组合关系：应用要求＋基础板支持包＋组件包＋接线配置 → 能力与资源检查 → 构建固件 → 实机验证。

网络：首期直接使用 S3 自带 Wi-Fi，不采购外置 Wi-Fi 模块。触摸与显示分别适配；带触摸屏只是将两种能力集成在同一设备上，不能把触摸视作所有显示设备的必需能力。

首批组合 A / B 与下一步 B2

配置硬件与输入要证明的事情
A · 固定产品板CoreS3，16 MB Flash / 8 MB PSRAM；板载 320×240 触摸屏。音频先不作为必需能力。完整板级包能让应用快速运行；触摸转换为开始、暂停、确认等业务动作。
B · 自由接线组合DevKitC-1 N8R8，8 MB Flash / 8 MB PSRAM；外接 ST7789 240×240 非触摸屏＋两个按键。应用不依赖触摸；基础板、屏幕组件和输入组件能独立组合。
B2 · 首轮通过后追加沿用 B 的 DevKit，换一块有文档的 ST7789 240×320 SPI 屏；暂不下单。屏幕模块参数仍需单独验证。只改组件参数 / 组合配置和布局选择，不复制应用与驱动。若初始化不兼容，增加明确的模块配置，而非假定同控制器即可互换。

B2 是后续增量验证，不属于当前预算与排期。再往后选择圆屏或旋钮，用新增组件检验接口；不要同时增加芯片、屏幕和输入方式三个变量。

01 · 应用：先验证，再增加传播力

顺序应用与范围验证什么
P0 · 专注时钟开始 / 暂停 / 重置、倒计时、进度、设置保存、完成动画。结束提示音为可选能力。显示、输入、时间、存储；触摸与实体按键统一为业务事件。
P1 · 桌面互动角色先使用自制简单表情与本地动画；触摸 / 按键触发互动，空闲切换状态。首版无麦克风、无模型依赖。第二个应用复用相同运行库和驱动；验证动画、素材和布局差异。
P2 · 可选 AI 对话先在 CoreS3 增加按住说话、文字回复；再按需要增加 TTS。先接一个后端，第二个后端用于验证连接器边界。网络、音频与 UI 并发；超时、取消、断网和服务切换。不是首轮通过的前置条件。

互动角色是体验与传播假设，不能预先称为爆款。邀请 3–5 名试用者实际使用，记录安装失败点与次日继续使用情况。

02 · 采购计划：一套集成设备＋一套外接组合

A 用来快速启动应用；B 用来验证换硬件后应用能否复用。两套都用 ESP32-S3。CoreS3 已经有屏幕，不用再给它买一块屏幕；独立屏幕和按钮是给 DevKit 配的。

购买项 / 数量所属组合与选型要求
CoreS3 标准版 × 1 台A：整机集成方案。16 MB Flash、8 MB PSRAM、320×240 触摸屏，集成麦克风与扬声器。核对具体版本，不能未经确认改买 CoreS3 SE。屏幕、触摸和音频不另购。
ESP32-S3-DevKitC-1-N8R8 × 1 块B：主控开发板。8 MB Flash＋8 MB PSRAM，PCB 天线、已焊排针版本。核对实物模组丝印、板级修订和原理图，不只看“S3”标题。
ST7789 屏幕模块 × 1 块B：外接显示。240×240、SPI、已焊排针，要求有接线图及供电 / 背光说明、支持 3.3 V 逻辑。购买带转接板的模块，不买裸屏；候选为 1.54 寸模块。
按键模块 × 2 个B：实体输入。选支持 3.3 V 逻辑、可直接接线的模块，用于开始、暂停、确认等动作。动作映射由应用与平台约定。
面包板＋杜邦线 × 1 套B：接线配件。备公对公、公对母线；核对开发板宽度及面包板可用空间。引脚分配在确认具体板与屏幕后确定。
USB 数据线，配齐两套A / B 共用要求。按实际 USB 接口配线，必须能传输数据。已有合适线材就不重复购买；首轮使用可靠 USB 供电。
万用表 × 1 个（已有则不买）用于接线、供电与导通排查。首轮暂不采购示波器或专用测试夹具。

购买顺序

  1. 推荐分步：先确认 CoreS3 标准版库存与配置，购买 A＋所需数据线，点亮屏幕并跑通时钟。同步确认 B 的开发板、屏幕资料和接线。
  2. 随后补 B：采购 DevKit＋屏幕＋按钮＋接线配件，执行同一应用跨硬件验证。
  3. 想减少等快递：两套规格都核对清楚后可一起买，但实施仍先 A 后 B。到货等待不计入有效工作日。

暂时不买：外置 Wi-Fi 模块（S3 自带 Wi-Fi）、电池、额外麦克风 / 扬声器、C3 / C6 开发板，以及 B2 的第二块屏幕。

预算预留：A 约 ¥350–650；B＋屏幕＋接线约 ¥120–250；数据线 / 万用表约 ¥80–200，合计约 ¥550–1,100。均为规划估算；配件若已有或套装已包含，不重复购买。实际价格和配送库存未核实，不作为报价。

03 · 中间平台：只构建支撑这四个组合的最小内核

构件首期实现复用 / 暂缓
能力契约显示尺寸 / 格式、输入事件、时间、配置存储；应用声明 required / optional 能力。音频为后续可选接口。不要一开始定义所有传感器和总线 API；不做通用驱动自动生成。
应用 API 与运行库C/C++；统一启动 / 停止、事件队列、配置存取与错误；UI 使用 LVGL 布局，应用禁止写板型与 GPIO 分支。直接复用 FreeRTOS、LVGL、NVS；薄封装而非再造 GUI 或调度系统。直接使用 LVGL 的部分绑定版本，不宣称 GUI 后端可随意切换。
硬件支持包A 提供完整板级包；B 拆为 DevKit 基础包＋ST7789 组件＋按键组件＋组合配置。触摸 / 按键转成统一动作。优先复用与锁定 ESP-IDF 兼容的官方 BSP / 驱动；屏幕方向、色序和偏移仍需实测。
匹配与构建先用 Python CLI＋JSON 清单，校验能力和依赖，生成配置，调用 idf.py；锁定源码提交、SDK 与组件版本。先选能跑通两套 BSP 的稳定 ESP-IDF 版本，不猜最新版本；不先做云编译、账号或应用商店。
交付与验证本地 USB flash / monitor；输出固件、锁文件、构建日志、测试记录；打包清单关联硬件修订与产物摘要。首期手工实机用例＋可重复构建脚本即可；OTA、签名和自动化夹具另设阶段。

建议命令形态（仅接口草案，尚未实现）：platform build --app focus-clock --hardware cores3-default → platform flash --port …。相同应用切换 --hardware s3-devkit-st7789-buttons，业务源码保持不变。

04 · 启动路线：每个阶段都必须拿出可运行结果

阶段 / 时间假设工作与交付物通过门槛 / 不通过怎么办
G0 · 到货前，1–2 日确定清单和接口草案；建示例仓库结构；用主机端状态机 / LVGL 预览验证时钟逻辑。整理 BSP 与 SDK 版本兼容信息。有应用状态图、硬件清单与候选依赖；不把模拟通过当成硬件验证。
G1 · 到货后，2–3 日先跑厂商示例：两套硬件各自点亮屏幕、读输入、识别 Flash / PSRAM，记录丝印与修订。每套能重复烧录和重启；驱动卡住则先修硬件基线，不同时调试平台抽象。
G2 · 3–4 日实现最小接口与 CoreS3 BSP，交付专注时钟；加入配置保存与本地日志。开始 / 暂停 / 重置、结束动画和设置持久化可用；不依赖公网。
G3 · 3–4 日拆出 DevKit 基础包、ST7789 驱动、按键组件与接线配置；统一输入事件，适配方屏布局，接入 CLI 匹配与构建。同一应用业务源码跨两套硬件运行；若出现板型分支，调整接口或把差异移回 BSP。
G4 · 3–4 日加入互动角色应用，两板复用已有支持包；完成 2×2 验证矩阵和版本锁定。四个组合都通过基本交互与稳定性检查；新增应用不得复制驱动代码。
G5 · 2–3 日整理安装文档与演示，邀请一名外部开发者安装、构建；对外发布首个可复现开源版本前检查许可证与资源来源。外部开发者按文档独立完成；失败点先修文档 / 工具。再决定接入 AI、扩板或做 OTA。

05 · 首轮验收矩阵

组合（全部待验证）显示与输入离线 / 配置 / 稳定性
时钟 × CoreS3横屏＋触摸动作必须通过
时钟 × DevKit 组合方屏＋实体按键必须通过
互动角色 × CoreS3动画＋触摸互动必须通过
互动角色 × DevKit 组合动画＋按键互动必须通过
  • 各组合至少连续运行 8 小时，无崩溃；热身后观察空闲堆内存是否持续下降。
  • 各组合做 20 次交互循环、10 次重启；设置保存后可恢复。
  • 从新构建目录按锁文件重建；记录产物摘要，不把可复现流程误称为已实现逐字节一致。
  • 移除必需显示能力或配置 GPIO 冲突时，构建前报错；禁用可选音频时视觉提醒仍可用。

验证记录必须包含板型 / 修订、模组与内存、屏幕模块、接线配置、软件锁版本。这些是建议的工程验收线，不是量产可靠性认证。

06 · 下一阶段的进入条件

  • 加 AI：四个离线组合先通过；先做文字请求，再引入采音和 TTS。
  • 先换外设：A / B 四个组合通过后，在同一 DevKit 上验证 B2；检查驱动是否真正可复用。
  • 再加板：让第三方按文档提交 S3 支持包；新增板不修改应用业务。
  • 最后扩芯片：S3 包结构稳定后，选择 C3 或 C6 中的一种。用轻量时钟验证迁移及资源不足诊断；需要 Thread / Zigbee 时再优先评估 C6。单独安排采购、能力验证与排期，不承诺所有 S3 应用均可迁移。
  • 加 OTA：确认两板固件大小和分区预算，再设计 A/B、启动确认及断电恢复。
  • 加云服务：已有用户确实需要远端构建或设备群管理，再投入托管基础设施。
