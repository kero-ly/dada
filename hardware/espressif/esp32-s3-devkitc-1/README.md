# ESP32-S3-DevKitC-1（N16R8）· 第二块板

**状态：计划采购，未验证。**

## 为什么选它

第二块板的价值不在于「多支持一块」，而在于**逼出第一版抽象里的错误**。所以它必须和首板差得够远：

| 维度 | 首板（C3 一体板） | 第二块（S3 DevKitC + 独立屏） | 能压力测试什么 |
| --- | --- | --- | --- |
| MCU | RISC-V 单核 160MHz | Xtensa 双核 240MHz | 契约是否被架构细节污染 |
| 内存 | 320KB SRAM，无 PSRAM | 512KB SRAM + **8MB PSRAM** | 双缓冲 / 解释器路线 |
| 屏幕连接 | 焊死在一体板上 | **独立 SPI 模块 + 杜邦线** | 板 / 屏 / 触摸能否真正解耦 |
| 触摸 | CST836U（I²C） | GT911（I²C）或 XPT2046（SPI） | `input` 契约是否抽象到位 |
| USB | 仅 USB-Serial/JTAG | **USB-OTG + USB-Serial/JTAG 双控制器** | `usb.mode` 字段是否够用 |

**关键：必须买“分离式”，不要买又一块一体带屏的板。** 一体板只能验证“换了个更大的板”，
逼不出任何抽象问题。

## 建议采购组合（约 120 元）

| 件 | 型号 | 说明 |
| --- | --- | --- |
| 主控板 | ESP32-S3-DevKitC-1 **N16R8** | 16MB Flash + 8MB PSRAM，Octal PSRAM |
| 屏模块 | 2.8" 或 3.5" SPI，ILI9341 或 ST7789，**带触摸排线** | 与首板不同控制器更好（ILI9341） |
| 触摸 | 模块自带 GT911（I²C）或 XPT2046（SPI） | 优先 GT911，和 CST836U 同为 I²C 但协议不同 |

## 这次选型暴露的问题（重要）

DevKitC 本身**没有屏幕也没有触摸**。但当前的 `board.json` 模型假设「一块板 = 板 + 屏 + 触摸」，
这在首板成立（一体板），在这里不成立。

三个选项：

1. **清单里 `display: null`，另建 `hardware/modules/`** 描述可插拔的屏与触摸模块，
   由 `hardware/<board>/compose.json` 声明「本板 + 这些模块」。
2. 给清单加 `modules: []` 字段，允许引用模块 id。
3. 不做组合，每套组合单独一个 `board.json`（会导致清单爆炸）。

倾向 **方案 1**：让「板」和「模块」成为两类一等公民，才符合“自由组合”的产品定位。
已作为未决问题记入 [ADR 0002](../../../docs/adr/0002-board-manifest.md)。
