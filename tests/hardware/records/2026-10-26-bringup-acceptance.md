# 验收记录 · 2026-10-26 · bringup（触摸坐标 + 冷启动）

对应路线图 **Acceptance gate 2**（counter loop）中尚未验收的两项：
触摸坐标与屏幕位置的对应、断电冷启动行为。

- 板卡：金逸晨 ESP32-C3 2.4 寸触摸开发板
- 工具链：ESP-IDF v5.4.2（仓库基线），`DADA_APP=bringup`
- 主持：`bringup`（网格验收版），烧录后由用户操作、AI 记录日志

## 方法

`apps/bringup` 已从"只看色带"升级为验收工具：

- 屏幕画 **3×3 网格**，每格中央用 5×7 点阵标出编号 1~9；
- 触摸时在触点画 11×11 红色标记（只刷新该矩形），并在串口打印
  `tap (x, y) -> cell N (row r col c)`；
- 触摸抬起打印 `release`。

这样"点了哪一格"和"驱动报了什么坐标"可以逐条对照，而不是只看有没有坐标。

## 结果一：触摸坐标对应 —— 通过 5/5

用户按 `1 → 3 → 5 → 7 → 9` 的顺序点击，串口记录：

| 用户所点 | 重报坐标 | 判定格 | 结论 |
| --- | --- | --- | --- |
| 左上 | (15, 56) | 1 (row 1, col 1) | ✅ |
| 右上 | (199, 60) | 3 (row 1, col 3) | ✅ |
| 中心 | (110, 154) | 5 (row 2, col 2) | ✅ |
| 左下 | (41, 281) | 7 (row 3, col 1) | ✅ |
| 右下 | (177, 258) | 9 (row 3, col 3) | ✅ |

结论：坐标原点在左上，X 向右、Y 向下，**无镜像、无轴交换、无缩放偏差**。
当前驱动直接使用面板原始值（0..239 / 0..319），不需要映射。

## 结果二：断电冷启动 —— 通过

操作：拔掉 USB → 等 3 秒 → 插回（不按任何键）。抓到的启动日志：

```
rst:0x15 (USB_UART_CHIP_RESET),boot:0xf (SPI_FAST_FLASH_BOOT)
I (24) boot: ESP-IDF ... 2nd stage bootloader
I (206) display_st7789: ST7789 240x320 ready
I (286) touch_cst836u: CST836U at 0x15, touches=0
bringup: 240x320 grid ready, tap each numbered cell
I (336) app_host: bringup started (240x320)
```

结论：**单次干净启动**，336ms 内显示与触摸就绪，无 panic、无重启循环。

## 未覆盖（不要当成已验证）

- 长按、滑动、多点触控
- 屏幕边缘（x<4 / x>236、y<4 / y>316）的坐标精度
- 长时间运行（>30 分钟）的稳定性
- 冷启动时的画面是否与复位启动完全一致（本次只看了日志）

## 复现步骤

```bash
idf.py -DDADA_APP=bringup build flash
# 依次点击 1、3、5、7、9，对照串口输出
# 然后拔插 USB，确认启动日志只有一轮
```

> 注意：`DADA_APP` 是 CMake cache 变量，切换后会被记住。
> 回到默认应用需要显式传 `-DDADA_APP=touch-counter`，否则会一直构建上一次的选择。
