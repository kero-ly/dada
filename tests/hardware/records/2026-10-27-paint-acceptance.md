# 验收记录 · 2026-10-27 · 像素画板

第二个"好玩"的应用，验证 `display + input + storage` 能不能做出**有留存价值**的东西。

- 板卡：金逸晨 ESP32-C3 2.4 寸触摸开发板
- 工具链：ESP-IDF v5.4.2，`DADA_APP=paint`

## 结果：可画、可保存 —— 通过

| 操作 | 期望 | 实测 |
| --- | --- | --- |
| 启动 | 顶部 8 格调色板，下面 24×28 网格 | 通过 |
| 点色块 | 选中颜色，白框标记 | 通过 |
| 滑动画线 | 连续笔迹，无断点 | 通过（用户确认） |
| 点第 8 格 | 清空整幅 | 通过 |
| 抬手后保存 | 写入 NVS | 通过 |
| 复位后启动 | 读回位图 | 通过 |

串口证据：

```
paint: 24x28 cells ready, tap a colour then draw   ← 首次绘制
paint: restored 672 bytes                          ← 复位后读回上次的位图
paint: 24x28 cells ready, tap a colour then draw
```

## 过程中做的一个决定：storage 加 blob

画板要保存一张 672 字节的位图，而 `storage` 当时只能存 u32。

这不是"想加能力"，是应用逼出来的需求：**没有持久化，画板就是个玩具**。
所以扩展了契约，新增 `set_blob` / `get_blob`，上限 `DADA_STORAGE_BLOB_MAX = 1024`。

契约仍然小：只有 u32 + 有界 blob，不引入分配语义，也不引入文件系统。
NVS 直接支持 blob，实现只有 30 行。

## 实现里值得记的两处

**穿点补线**：触摸采样是每帧一次，快速滑动会在两个采样点之间跳过好几格。
用 Bresenham 连接相邻采样点，笔迹才连续。测试里专门验了斜线不漏格。

**越界裁剪而不是放弃**：手指滑出画区时，线段端点落在界外。
第一版 `paint_stroke` 直接返回失败（什么都不画），测试立刻抓到——
改成裁剪到边界内继续画，返回值表示"是否画到至少一格"。
